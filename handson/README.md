# ハンズオン：Copilot Studio で Agent Skills を作成・使用する

Copilot Studio の GitHub Copilot エージェントに Agent Skills を追加します。パート 3 で追加方法ごとにスキルを作成し、パート 5 でそのスキルの動作を確認し、パート 7 で自分たちの業務のスキルを作成します。

| パート | Step | 内容 | 時間 |
|---|---|---|---|
| 3 追加方法と管理 | Step 0〜3 | エージェントの作成、「最初から作成」「.md」「.zip」でのスキル作成 | 35分 |
| 5 演習 | Step 4〜5 | 作成したスキルの動作確認、振り返り | 20分 |
| 7 自分たちでスキルを作成 | Step 6 | 自分たちの業務でスキルを設計・作成 | 35分 |

- 題材の規程は **ハンズオン用の架空の規程** です。外部データや接続は使用しません。
- 受講者は「Step 0」から進めてください。「事前準備」と末尾の「講師メモ」は講師・管理者向けです。

## 配布物

配布物は [GitHub リポジトリ](https://github.com/SeiyaTogawa/copilot-studio-agent-skills-workshop) の `handson/` フォルダにあります。ファイルを開き、右上の **Download raw file** でダウンロードしてください。

| ファイル | 用途 |
|---|---|
| [`dist/expense-policy-check.md`](dist/expense-policy-check.md) | Step 2 でアップロード（SKILL.md 単体） |
| [`dist/expense-policy-check.zip`](dist/expense-policy-check.zip) | Step 3 で置換（SKILL.md ＋ references/ ＋ assets/） |
| [`expense-policy-check/`](expense-policy-check/) | zip の中身（講師用の原本。編集後は `build_dist.py` で再生成） |

zip の中身：

```text
expense-policy-check.zip
├── SKILL.md                             … 名前・説明・手順
├── references/expense-policy.md         … 架空の経費精算規程（第1〜9条）
├── assets/result-template.md            … 出力フォーマット
└── assets/expense-policy-original.pdf   … 規程の原本（NG・要確認のときに回答へ添付）
```

## 事前準備（講師・管理者）

- 受講者が使用する環境で **GitHub Copilot エージェントを作成できる** こと（ホームに「エージェント [GitHub Copilot]」が表示される）
- その環境に **Copilot クレジットが割り当てられている** こと
  - 割り当てがない場合、プレビューで `This environment is out of credits`（`EnforcementUsageCredits`）が返ります
- 「スキルの追加」の **Generate with AI（AI で生成）はプレビュー機能のため、環境によっては表示されません**。受講者の演習は「最初から作成」と「アップロード」のみで完結します
- 講師デモ用に、Generate with AI が表示される環境で GitHub Copilot エージェントを 1 つ用意しておく

# パート 3：追加方法ごとのスキル作成

## Step 0：演習用エージェントの作成（5分）

1. Copilot Studio にサインインし、左下の環境名が指定の環境であることを確認する
2. ホームの **エージェント [GitHub Copilot]** を選択する
3. 名前：`経費アシスタント（自分の名前）`
4. 指示：

   ```text
   あなたは社内の経費精算をサポートするアシスタントです。日本語で丁寧に回答してください。
   ```

5. 右パネルの **ナレッジ** に「すべての Web サイトを検索する」があれば削除する（スキルの効果を確認しやすくするため）
6. **保存**

保存後、右パネルに **スキル** の欄があれば準備完了です。表示されない場合は「うまく動作しない場合」を確認してください。

## Step 1：「最初から作成」で business-trip-report を作成（10分）

1. 右パネルの **スキル** →「スキルの追加」→ **最初から作成**
2. 次の 3 項目を入力して **作成**

   名前：

   ```text
   business-trip-report
   ```

   説明：

   ```text
   出張の報告書を作成する。「出張報告を書きたい」「出張のまとめを作って」など、出張後の報告・共有を頼まれたときに使う。
   ```

   指示：

   ```markdown
   # 出張報告書の作成

   ## 手順
   1. 出張先、日程、訪問先、目的、結果、次のアクションを聞き取る。足りない項目は1回だけまとめて質問する。
   2. 次の見出しで報告書を作る：概要 / 訪問先と目的 / 結果 / 次のアクション / 経費メモ
   3. 最後に「経費精算が必要な項目」を箇条書きにする。

   ## 注意
   - 推測で事実を書かない。不明な点は「（未確認）」と書く。
   ```

3. **プレビュー** タブで次のプロンプトを送信する

   ```text
   昨日の大阪出張の報告書を作って。訪問先はA社、目的は新サービスの提案。先方は前向きで、来月に再訪問する予定。
   ```

4. 確認ポイント
   - 回答の上に `Used skill: business-trip-report` が表示される
   - 指示で指定した見出しの報告書が作成される

## Step 2：expense-policy-check.md のアップロード（10分）

まずは SKILL.md 単体で、スキルの手順が回答に反映されることを確認します。

1. 「スキルの追加」→ **スキルのアップロード** → `dist/expense-policy-check.md` を選択する
2. スキル一覧に `expense-policy-check` が追加されたことを確認する（アップロード時に自動で保存されます）
3. **プレビュー** →「新しいチャット」→ 次のプロンプトを送信する

   ```text
   取引先と4人で会食して合計40,000円でした。領収書はあります。参加者の名前は書いていません。経費として申請して大丈夫かチェックして
   ```

4. 確認ポイント
   - `Used skill: expense-policy-check` が表示される（処理中は `Using skill: …`）
   - SKILL.md の手順どおり、OK / 要確認 / NG の判定表で回答される
   - ファイルがない場合の指示どおり、回答の冒頭に「※社内規程ファイルが同梱されていないため、一般的な観点での判定です」という趣旨の注記が表示される（規程を持たないため、上限額などの具体的な数値は示さない）
   - 回答の末尾に、原本 PDF を添付できない旨と、経理部門への確認の案内が表示される

## Step 3：zip への置換（10分）

同じスキルに規程・テンプレート・原本 PDF を同梱し、同梱ファイルも参照して回答することを確認します。

1. スキル一覧の `expense-policy-check` を選択し、詳細パネルの **…** → **置換**
2. `dist/expense-policy-check.zip` を選択する（アップロード時に自動で保存されます）
3. `expense-policy-check` の詳細パネルを開き、`SKILL.md` / `assets/expense-policy-original.pdf` / `assets/result-template.md` / `references/expense-policy.md` が表示されることを確認する
4. **プレビュー** →「新しいチャット」→ Step 2 と同じプロンプトを送信する
5. 確認ポイント
   - 判定の根拠に **条文番号**（例：第7条1項）が付く
   - 出力が `assets/result-template.md` の形式（判定表・総合判定・申請者へのコメント案・参照した条文）になる
   - 回答の末尾に「規程の原本（PDF）を添付しました」と、`expense-policy-original.pdf` のファイルが表示される

> zip で置換した後のスキルには「…」が表示されません。zip のスキルを更新する場合は、削除してから再アップロードします。

# パート 5：演習（作成したスキルの動作確認）

## Step 4：追加のテスト用プロンプト（15分）

Step 1〜3 で作成した 2 つのスキルを使用し、判定の内容と呼び出しの有無を確認します。プロンプトごとに「新しいチャット」で送信してください。

- **Step 4-1（10分）**：#1〜3 で、判定と条文番号を確認
- **Step 4-2（5分）**：#4〜5 で、呼び出されるスキルを確認

| # | プロンプト | 期待される結果 |
|---|---|---|
| 1 | `昨日23時に客先から会社までタクシーで8,500円。領収書あり。` | ✅ OK：22時〜翌5時の乗車（第5条1項）、上限10,000円以内（第5条2項） |
| 2 | `大阪出張で1泊14,000円のホテルに泊まりました。` | ⚠️ 要確認 または ❌：大阪市の上限12,000円を超過、差額2,000円は自己負担（第6条） |
| 3 | `2か月前の交通費1,200円を申請したい。レシートはなくしました。` | ⚠️ 要確認：30日超のため遅延理由＋上長承認（第2条2項）、3,000円未満は出金伝票で代替可（第3条2項） |
| 4 | `先週、福岡のB社を訪問しました。出張報告をまとめたいです。` | `business-trip-report` が呼び出される：不足している項目（日程・目的・結果など）をまとめて質問する |
| 5 | `会議室の予約方法を教えて` | スキルは呼び出されない（経費・出張報告のいずれとも無関係） |

> 生成 AI の回答は毎回多少異なります。判定の結論と条文番号が一致していれば問題ありません。判定に ⚠️ 要確認・❌ NG がある場合は、規程の原本 PDF も添付されます。

## Step 5：振り返り（5分）

- md 単体と zip で何が変わったか（規程の数値・条文番号・出力形式・原本 PDF の添付）
- スキルが呼び出されるかどうかを決めているのはどこか（`description`）
- 規程が改定された場合、どこを修正し、どう反映するか（原本を修正 → zip を再作成 → 削除して再アップロード）

# パート 7：自分たちでスキルを作成

## Step 6：自分たちの業務でスキルを作成（35分）

毎回同じ手順・形式で回答してほしい業務を 1 つ選び、スキルとして作成します。個人またはペアで進めてください。

| フェーズ | 内容 | 時間 |
|---|---|---|
| 1. 業務の選定 | 規程チェック、報告書作成、問い合わせへの一次回答など | 5分 |
| 2. 設計 | 下記の設計シートに沿って、description・手順・出力形式・テスト依頼を決定 | 10分 |
| 3. 作成・テスト | 「最初から作成」で作成し、呼び出されるべき依頼とそうでない依頼でテスト | 15分 |
| 4. 共有 | 数名が、作成したスキルとテスト結果を紹介 | 5分 |

### 設計シート

| 項目 | 決める内容 |
|---|---|
| name | 英小文字・数字・ハイフン（例：`meeting-minutes`） |
| description | 何をするか ＋ どんな依頼で使うか。ユーザーが実際に使う表現を含める |
| 手順 | 番号付きで 1 ステップにつき 1 動作。情報不足時の動作も記載 |
| 出力形式 | 見出し・表など、毎回そろえたい形式 |
| テスト依頼 | 呼び出されるべき依頼を 1 つ、呼び出されるべきでない依頼を 1 つ |

description のひな形：

```text
<何をするか>。「<依頼の例 1>」「<依頼の例 2>」など、<どんなとき>に使う。
```

指示のひな形：

```markdown
# <スキルの目的>

## 手順
1. <確認する項目>を聞き取る。足りない項目は1回だけまとめて質問する。
2. <処理の内容>
3. 次の見出しで回答する：<見出し 1> / <見出し 2>

## 注意
- 推測で事実を書かない。不明な点は「（未確認）」と書く。
```

テストの確認ポイント：

- 呼び出されるべき依頼で `Used skill: <スキル名>` が表示される
- 呼び出されるべきでない依頼で表示されない
- 余裕があれば「ダウンロード」で md を保存し、手元で編集して差し替える（削除 → 再アップロード）

## うまく動作しない場合

| 症状 | 原因と対処 |
|---|---|
| `This environment is out of credits` | 環境に Copilot クレジットが割り当てられていない。講師に連絡する |
| 「スキルの追加」が表示されない | GitHub Copilot エージェントではない。従来型（標準ハーネス）のエージェントには Skills がないため、Step 0 からやり直す |
| アップロードしたスキルが一覧に表示されない | フロントマター（`---` で囲まれた部分）の YAML が不正、`name` / `description` がない、UTF-8（BOM なし）でない、など |
| スキルが呼び出されない | `description` が依頼内容と合っていない。「どんな依頼のときに使うか」を具体的に記述する |
| 「スキル名が重複しています」でアップロードできない | 同じ `name` のスキルが既に存在する。md のスキルは「… → 置換」、zip のスキルは削除してからアップロードする |
| 置換したのに回答が変わらない | 「新しいチャット」で会話をやり直す |

## 講師メモ：配布物の再生成

`expense-policy-check/` 配下を編集したら、次のコマンドで `dist/` を再生成します（フロントマターと文字コードのチェック付き）。`references/expense-policy.md`（規程）のほうが新しい場合は、原本 PDF（`assets/expense-policy-original.pdf`）も Microsoft Edge で作り直します。強制的に作り直す場合は `--pdf` を付けます。

```powershell
$env:PYTHONIOENCODING='utf-8'; python build_dist.py
```
